# Feature Specification: Сабміт (submission)

**Feature Branch**: `004-submission`

**Created**: 2026-10-23

**Status**: Draft

**Input**: PRD «Inside the Block» — Deliverables, критерії оцінювання, дедлайн ~5.11.2026.

## User Scenarios

### Суддя відтворює все за README (P1)

Суддя клонує репо, читає README і за ≤10 хв: запускає dry-run, ганяє
`verify` на прикладених даних, бачить таблицю design-validity і чесний
список невідокремленого, знаходить сирі дані і скрипт `analyze`.

### Оператор виходить на live (P1)

Оператор за README-інструкцією: кладе ключі у `./keys`, задає RPC через env,
перевіряє dry-run, ставить `MODE=live`, стежить за леджером. Бюджет тримає код.

## Requirements

- **FR-004-01**: README MUST містити: запуск однією командою, dry-run/live
  режими, таблицю design-validity (6 пунктів PRD «Що треба врахувати» +
  як закрито), список того, що НЕ відокремлюється, бюджет і ключі.
- **FR-004-02**: `analyze` CLI MUST з `data/` рахувати метрики 003 на
  (validator, arm) і друкувати Markdown/CSV таблиці.
- **FR-004-03**: `verify --live-check` MUST перезапитувати `getBlock` з RPC
  і звіряти позиції; розбіжність з ланцюгом → non-zero exit.
- **FR-004-04**: Звіт-скелет MUST мати: дати вимірювань, версії конфігу і
  валідаторів, таблицю вердиктів, графіки-заготовки, розділ «що пішло не так».
- **FR-004-05**: Чекліст сабміту MUST покривати всі 8 deliverables PRD зі
  статусами (що готово кодом, що чекає live-даних).

## Success Criteria

- **SC-001**: Новий читач виконує README end-to-end без звернень до авторів.
- **SC-002**: `analyze` на синтетичному `data/` дає очікувані вердикти.
- **SC-003**: `verify --live-check` проти локального стаба проходить/ловить
  розбіжність.
